## What is a Distributed System? (Simple definition)

A **distributed system** is when:

> Multiple independent services or machines work together over a network to behave like **one system**.

Examples you already use:

* Backend APIs talking to **databases, caches, message queues**
* **Microservices** calling each other
* Systems that **must not go down** if one part fails

If your backend runs on **more than one server** → you’re in distributed systems.

---

## Core Topics in Distributed Systems (Industry-Relevant)

### 1️⃣ **Service Communication**

How services talk to each other.

You should know:

* HTTP/REST
* gRPC
* Service discovery
* API gateways

Why it matters:

* Latency
* Failures
* Versioning

👉 **Go & Java are heavily used here**

---

### 2️⃣ **Concurrency & Parallelism**

Multiple tasks running at the same time.

Concepts:

* Threads vs async
* Locks, mutexes
* Race conditions
* Deadlocks

Languages:

* Go → goroutines, channels
* Java → threads, executors
* Rust → ownership + safe concurrency

This is **non-negotiable** for backend interviews.

---

### 3️⃣ **Data Consistency & CAP Theorem**

You **cannot** have everything.

You must understand:

* CAP theorem (Consistency, Availability, Partition tolerance)
* Strong vs eventual consistency
* Read replicas
* Quorum reads/writes

Used in:

* Databases
* Caches
* Distributed services

---

### 4️⃣ **Databases in Distributed Systems**

Not just CRUD anymore.

Topics:

* Sharding
* Replication
* Leader–follower
* Failover
* Transactions across services

Databases to know:

* PostgreSQL (replication basics)
* Redis (replicas, clustering)
* MongoDB (replica sets)

---

### 5️⃣ **Caching**

Used everywhere to scale systems.

Concepts:

* Cache-aside vs write-through
* TTL & eviction
* Cache consistency problems
* Redis cluster

Why it matters:

* Performance
* Cost
* Availability

### 6️⃣ **Message Queues & Event Systems**

Critical for decoupling services.

Tools:

Concepts:
